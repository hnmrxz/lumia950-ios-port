## Emulation

- The `kernel` job is green with the pthread component linked (runs 45314032032, 45318161131). The gate
  in `scripts/check-kernel-link.py` asks for the component's global symbols because the linker emits its
  entry as a non-external `__startup_EARLY_BOOT_entry_source_pthread_bootstrap_NN` that `nm -gU` hides.
- The emulated boot **returns from BSD initialisation**: run 45587399756 prints `!BSD`, then waits for an
  `IOMedia` whose `Content` is `Apple_HFS`, and reports `Still waiting for root device`
  (`docs/emulation/2026-11-25-bsd-init-crossed.md`). `_vfs_mountroot` is still never reached.
- **The emulated branch has a measured ceiling**, written down in
  `docs/emulation/emulated-branch-limits.md`: a synthetic root media cannot exist in the source link
  (force-loading it fails on undefined `IOBlockStorageDevice::*`, run 45706495971); the pinned XNU has no
  `bsd/hfs` and no memory disk, so no ramdisk root either; and the merged image goes silent after the
  kernel hand-off (serial of run 45715174239), so a claim about how far it gets would be inference.
  `docs/emulation/root-device-design.md` carries the design history behind those three facts.
- Those runs carry the `skmem_sysctl_skip` guard from `ci/skmem-skip.py`, compiled into the tree before
  the build. Reports classify them as `panicked` because the idle thread null-dereferences while waiting
  for the root device, after `!BSD` has already been printed.

## Handset

- Boot chain, its four corrections and the procedure that matches the evidence live in
  `docs/hardware/handset-boot-chain.md`; this page does not repeat them.
- **Deployment and rollback are rehearsed offline.** `scripts/rehearse-phone-install.py` runs the
  installer's dry run, then the runbook's single install-and-verify command against a reference store and
  against a drifted one; `scripts/rehearse-phone-rollback.py` snapshots a synthetic EFIESP, damages the
  store, proves the dry run writes nothing, and proves `--apply` restores and verifies it. The procedure
  they back is `docs/hardware/post-unlock-runbook.md`.
- The boot store is checked in three layers, in the order the firmware sees them: `{bootmgr} path` must be
  `\efi\boot\bootarm.efi`, `{bootmgr} default` must name an entry, and that entry must be the MainOS shim
  (`scripts/check-bcd-layout.py`). `phone-install.py --verify-bcd <enum>` runs that check in the same
  command as the install and fails the install when the store disagrees.
- **The chain now boots on the handset.** After the Windows-on-ARM deployment was applied, the phone walked
  firmware -> `bootarm.efi` -> the deployment tool's ARM32 `BootShim.efi` (subsystem 0x10) -> its `UEFI.elf`
  (LumiaWoA 2.16385) -> `EFI\BOOT\BOOTAA64.EFI` (this port's loader) -> the UniXNU 0.1.0 menu ->
  DarwinBoot's hand-off, with the kernel read from MainOS through the staged NTFS driver and the real panel
  reported as 1080x1920, row 4320 bytes, 32 bpp at 0x400000. Measurements, including the two failures that
  preceded it, are in `docs/hardware/2026-11-26-first-hardware-boot.md`.
- `XNU-entry-tested` is **not** claimed for the handset: no kernel line had been observed after the hand-off
  when that note was written.
- `--unique-chip-id` in the handset ADT is still a zero placeholder
  (`docs/hardware/2026-11-24-device-identity.md`).
- Recovery is either an FFU flash (`scripts/phone-recover.ps1`, donor FFU for the unlock) or a snapshot
  restore (`scripts/phone-snapshot.py`); an FFU cannot be generated by the tooling
  (`docs/hardware/2026-11-25-flashing-toolchain.md`). The four recovery scripts are parsed by the real
  PowerShell parser in `scripts/check-powershell-parses.py`, so a syntax error cannot hide there.

## Host tests must run on the CI host, not just here

A test added on 2026-11-25 asserted that a `C:\...` literal was absolute. That is true on Windows and
false on the Linux `validate` host, so it turned the job red the moment it was pushed. The same class of
bug came back on 2026-11-26, from the other side: `phone-snapshot.py` built its mount root as
`Path(value.rstrip("\\") + "\\")`, which only makes sense for `R:` and produced a non-directory on POSIX
(run 45711382502, `save exit: 2`). `mount_root()` now adds the separator only for a drive-letter form, and
the rehearsal that caught it runs on both hosts. `scripts/check-host-tests-portable.py` still reads every
test file and refuses a Windows absolute path inspected through `Path`/`open` instead of
`PureWindowsPath`; forty test files are clean.
