# State of the port

Only claims a run or a file here supports. Updated 2026-11-25; the previous snapshot was folded into
this page and removed.

## Emulation

- The `kernel` job is green with the pthread component linked (runs 45314032032, 45318161131). The gate
  in `scripts/check-kernel-link.py` asks for the component's global symbols because the linker emits its
  entry as a non-external `__startup_EARLY_BOOT_entry_source_pthread_bootstrap_NN` that `nm -gU` hides.
- The emulated boot crosses `bsd_init` (`past_bsd_outcome: stopped`), reaches `dlil_init`, and never
  reaches `_vfs_mountroot`.
- It stops in `skmem_sysctl_init`. The object exists and the address it points at is unmapped in this
  port's VA layout; the bypass is a proposal, not applied
  (`docs/emulation/2026-11-24-skmem-sysctl-skip-proposal.md`, `ci/skmem-skip.py`).

## Handset

- Boot chain, its four corrections and the procedure that matches the evidence live in
  `docs/hardware/handset-boot-chain.md`; this page does not repeat them.
- The install on the phone is not in a working state at the moment: the last unlock attempt did not
  complete (WPinternals stalls switching to mass storage before it can patch), the phone was flashed back
  to factory afterwards, and no boot of the custom chain has been observed.
- `--unique-chip-id` in the handset ADT is still a zero placeholder
  (`docs/hardware/2026-11-24-device-identity.md`).
- Recovery is either an FFU flash (`scripts/phone-recover.ps1`, donor FFU for the unlock) or a snapshot
  restore (`scripts/phone-snapshot.py`); an FFU cannot be generated by the tooling
  (`docs/hardware/2026-11-25-flashing-toolchain.md`).

## Host tests must run on the CI host, not just here

A test added on 2026-11-25 asserted that a `C:\...` literal was absolute. That is true on Windows and
false on the Linux `validate` host, so it turned the job red the moment it was pushed, and the same round
had to fix it. `scripts/check-host-tests-portable.py` now reads every test file and refuses a Windows
absolute path inspected through `Path`/`open` instead of `PureWindowsPath`; its own test is exempt because
it embeds such paths deliberately. Four tests cover the checker, and the suite is 29/29.
